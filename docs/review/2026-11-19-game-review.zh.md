# Level 0: Backrooms FPS — 游戏评估与改进方案

> **存档说明（2026-11-19 补交）**：这是对初版（提交 `609950f`）的第一次评估快照，原先只是会话临时文件夹里的未跟踪文件。第 1–3 阶段已在 PR #1–#4 完成，第 4 阶段的性能部分并入了 skill 审计第三批（PR #7）。**问题清单不代表当前状态**；之后的审计见 [2026-11-19-skills-audit.zh.md](2026-11-19-skills-audit.zh.md)。

- **评估对象**：`animenzzz128/level-0-survive`，commit `609950f`（2026-11-18）
- **评估方法**：读完全部源码（约 180 KB TypeScript）；本地 Vite 运行（Chromium 预览窗口，Intel 核显，1024×768）；用游戏自带的 `window.__BACKROOMS_DEBUG__` 接口跑了战斗、拾取、通关、重开等脚本化测试。
- **没覆盖到的**：真人键鼠长时间试玩、真实指针锁定下按 Esc 的表现、移动端、独立显卡上的帧率。

## 一句话结论

**画面和氛围做得很好，玩法和标榜的「生存恐怖」不符。** 程序化生成的墙纸、地毯、天花板贴图，荧光灯闪烁，全合成的 WebAudio 嗡鸣和心跳，完成度都很高。问题在于：弹药严重过剩，敌人杀完不会刷新，花 17 发子弹清场后整张地图就没有威胁了。另外有一个命中判定盲区，准星明明对着怪物胸口，子弹却打不中，非常伤手感。磁带和出口每局都在同一位置，重玩价值低。

## 问题清单

### P0：Bug（影响手感或正确性，修复成本低）

1. **三种怪物在胸口到脖子的高度都打不中。** 身体判定盒和头部判定盒之间留了一段空隙：
   - Howler：身体盒顶部 1.625、头部盒底部 1.91（[entities.ts:330](src/game/entities.ts:330)）
   - Smiler：1.525 / 1.605（[entities.ts:404](src/game/entities.ts:404)）
   - Skin-Stealer：1.60 / 1.77（[entities.ts:492](src/game/entities.ts:492)）

   玩家眼睛高度是 1.68（[maze.ts:179](src/game/maze.ts:179)），所以近距离平视时，Howler 和 Skin-Stealer 正好落在空隙里。被追到贴脸时是最需要打中的时刻，这时反而打不中。

2. **鼠标解锁或窗口失焦时游戏不暂停，按键还会卡住。**
   - `onPointerLockChange` 只刷新了 HUD（[BackroomsEngine.ts:932](src/game/BackroomsEngine.ts:932)）。
   - 没有监听 `blur` 和 `visibilitychange`。
   - Alt-Tab 时如果正按着 W，`keyup` 事件收不到，回来后角色会一直往前走。

3. **点击画面重新锁定鼠标时会顺带开一枪**（[BackroomsEngine.ts:970-977](src/game/BackroomsEngine.ts:970)）。枪声会把 26 m 内所有怪物拉进追击状态（[entities.ts:541](src/game/entities.ts:541)）。也就是说，玩家只是想继续游戏，结果把全图的怪都引了过来。

4. **`npm install` 失败**：devDependencies 里的 `esbuild@^0.25` 和 vite 8 冲突。仓库里只有 `bun.lock`，用 npm 的人第一步就会卡住。

5. **每次重开都泄漏 GPU 资源**：`clearGroups()` 只把物体从场景里移除，没有 dispose（[BackroomsEngine.ts:328](src/game/BackroomsEngine.ts:328)）。实测每局泄漏约 400–600 个 buffer。

### P1：设计问题（决定游戏好不好玩）

6. **资源太充裕，敌人数量有限，恐怖感很快消失。**
   - 敌人总血量：标准难度 485，噩梦难度 779。
   - 弹药（标准难度）：开局 72 发 + 6 箱 ×24 + 击杀 Brute 奖励 12 = 228 发。噩梦难度开局少 24 发，总共 204 发。
   - 清场所需：标准难度 17 发，噩梦难度约 25 发。
   - 敌人没有刷新机制（[BackroomsEngine.ts:790](src/game/BackroomsEngine.ts:790) 只在建关时生成一次）。

   结果是打一分钟枪，剩下的时间都是在空地图里散步。

7. **追击时跑不掉，只能打。** 走路速度 3.65 m/s，比 Howler 的 4.55 和 Smiler 的 4.95 都慢。冲刺 5.65 m/s 能跑过它们，但体力只够 4.5 秒（[BackroomsEngine.ts:1260-1266](src/game/BackroomsEngine.ts:1260)）。加上第 6 条的弹药过剩，玩家唯一的合理选择就是站着开枪。

8. **潜行机制几乎不起作用。**
   - 关手电只把发现距离缩短 4 m，以 Howler 为例是从 21 m 降到 17 m。
   - 怪物 7.5 m 内会**隔墙**直接进入追击（[entities.ts:581](src/game/entities.ts:581)）。
   - 脚步声和冲刺都不会引来怪物，只有枪声会，而且一开枪就是 26 m 范围全图唤醒。

9. **手电电池没有压力。** 耗电 0.55%/秒，关灯后回充 1.8%/秒（[BackroomsEngine.ts:1375-1382](src/game/BackroomsEngine.ts:1375)）。关 1 秒能换回 3 秒照明，所以杏仁水附带的「+35% 电量」实际没什么用。

10. **每局布局几乎相同。** 随机种子只影响走廊的连通方式，下面这些都是固定的：
    - 磁带位置（[maze.ts:213-218](src/game/maze.ts:213)）
    - 出口始终在右下角（[maze.ts:184](src/game/maze.ts:184)）
    - 出生点始终在左上角
    - 5 个大厅的中心位置（[maze.ts:144-150](src/game/maze.ts:144)）

    玩过一局之后，路线基本就记住了。

11. **地图读起来像迷宫，不像 Level 0。** 递归回溯算法生成的是单格宽走廊，墙是 3.2 m 厚的整块方块。Backrooms 原型给人的感觉是大小不一的空房间加上随机摆放的薄墙段，那种「空旷但不对劲」的感觉，现在的地图没有。

12. **没有空间音频。** 所有声音都直接接到 `dryGain`，没有 PannerNode（[audio.ts](src/game/audio.ts)）。怪物尖啸的音量固定为 0.32，传进去的距离参数被忽略了（[BackroomsEngine.ts:1361](src/game/BackroomsEngine.ts:1361)）。恐怖游戏里「听到身后有东西」是最便宜也最有效的恐惧来源，这里完全没用上。

13. **三种怪物只有数值不同，行为一模一样。** 它们共用同一套巡逻、追击、近战逻辑。死亡时直接 `visible = false` 瞬间消失（[entities.ts:519](src/game/entities.ts:519)），没有任何死亡反馈。

### P2：技术与工程

14. **性能**：核显上约 32 fps。可能的原因（尚未逐项验证）：
    - 场景里同时有 8 个灯池点光源、4 个磁带信标、出口灯、枪口灯，再加一盏带阴影的聚光灯，前向渲染下每个 PBR 材质都要算十几盏灯；
    - 每只怪由约 40 个小网格组成，而且全部开了 `castShadow`，阴影 pass 里会再画一遍；
    - pixelRatio 最高到 2。
15. 控制台有 `PCFSoftShadowMap has been removed` 警告（three r187），把 [BackroomsEngine.ts:207](src/game/BackroomsEngine.ts:207) 改成 `PCFShadowMap` 即可。
16. **生产环境也挂着调试接口**：传送、直接解锁出口等功能可以在控制台调用（[BackroomsEngine.ts:1586](src/game/BackroomsEngine.ts:1586)）。建议用 `import.meta.env.DEV` 包起来。
17. `BackroomsEngine.ts` 一个类 1733 行，输入、战斗、关卡构建、灯光、HUD 全混在一起。
18. **没有设置菜单**：`types.ts` 里定义了 `GameConfig.sensitivity`，但没有任何地方用到。没有灵敏度、音量、FOV 设置。另外空格键是开火，而一般玩家的习惯是空格跳跃。

### P2：仓库与展示（如果打算当作品集用，这部分很重要）

19. **没有 README，也没有在线试玩链接。** 招聘方打开仓库看不到截图、玩法说明和操作方式。
20. `.qa_shots/` 里有 31 张 PNG，共 **36 MB**，都提交进了仓库，克隆会很慢。
21. **AI Studio 模板残留**：
    - 包名还是 `react-example`；
    - `@google/genai`、`express`、`dotenv`、`motion`、`tsx` 等依赖在代码里都没有用到；
    - `metadata.json` 声明了服务端 Gemini 能力，`.env.example` 要求填 `GEMINI_API_KEY`，但游戏根本不调用 Gemini。别人克隆后会被这些配置误导。
22. 整个游戏只有 2 个 commit，看不出开发过程。
23. **署名**：
    - Level 0、Smiler、Skin-Stealer、Almond Water 等设定来自 Backrooms 社区 wiki，建议在 README 里注明来源。
    - 仓库里多处指向 Google AI Studio。按你自己对公开作品的规范，README 里应写明用了哪个 AI 工具、由你主导，具体工具以你实际用的为准。

## 改进路线图

### 第 1 阶段：修 bug，让项目能拿出来展示（约 1 天）

| 改动 | 做法 |
|---|---|
| 修命中盲区 | 每种怪物把身体盒顶部延伸到头部盒底部，例如 Howler 改成 `addHitbox(0.7, 1.65, 0.65, 1.1, false)`。同时加一个回归测试：在 0.3–2.3 m 每隔 0.1 m 发一条射线，断言全部命中 |
| 失焦自动暂停 | 指针锁从「锁定」变为「未锁定」且 `phase==='playing'` 时调用 `pauseGame()`；监听 `blur` 时清空 `keys`、取消瞄准并暂停 |
| 重新锁定不开枪 | 未锁定时的第一次点击只请求锁定，不开枪。保留拖拽视角的降级路径，供不支持指针锁的环境使用 |
| GPU 资源释放 | 把每关新建的几何体和材质记到一个 disposables 列表里，`clearGroups` 时逐个 dispose。注意 `this.materials` 里是共享材质，**不能**一起 dispose |
| 依赖清理 | 删掉 `esbuild`、`tsx`、`express`、`@types/express`、`dotenv`、`@google/genai`、`motion`；包名改成 `level-0-survive`；删掉或改写 `metadata.json` 和 `.env.example` |
| 仓库整理 | 把 `.qa_shots/` 移出仓库，挑 2–3 张压缩成 JPG 或做成 GIF 放进 `docs/` |
| README | 写清楚一句话卖点、动图、操作说明、技术亮点（程序化贴图、合成音频、实例化渲染）、设定来源和 AI 工具署名 |
| 部署 | 部署到 GitHub Pages 或 Vercel（Vite 配好 `base` 即可），README 顶部放试玩链接 |
| 调试接口 | 只在 DEV 环境安装 `__BACKROOMS_DEBUG__` |

### 第 2 阶段：从「射击」转向「生存恐怖」（约 1 周）

这里需要先定方向。**我建议恐怖优先**，因为 Backrooms 题材的核心是孤立感和无力感，而不是火力。

1. **收紧资源**
   - 开局 12+12 发，弹药箱减到 3 个，每箱 8 发。
   - 电池取消自动回充，改为拾取物。这样杏仁水和电池就成了需要权衡的选择。
2. **加一个威胁导演系统（Director）**
   - 每拿到一盘磁带，威胁升一级：灯光坏得更多，嗡鸣更响，在玩家视野外刷新一只新怪物。
   - 被杀死的怪物过一段时间会在视野外重生。

   这样整局会有一条自然上升的紧张曲线，而不是开头打完就结束。
3. **让三种怪物行为各不相同**（这是最能体现设计能力的部分）
   - **Smiler**：子弹打不死，只怕光。手电直射时它会后退或消散，但手电会耗电；关灯它就会慢慢靠近。手电因此从照明工具变成了一个两难选择。
   - **Howler**：靠听觉狩猎。冲刺脚步声和枪声会引来它，慢走不会。玩家要在「快」和「安静」之间做取舍。
   - **Skin-Stealer**：会伪装成拾取物（假杏仁水），或者静止站在走廊尽头。玩家会因此对每样东西都起疑心。
4. **噪音和潜行系统**
   - 按动作设定噪音半径：走路 3 m、冲刺 10 m、开枪 26 m。
   - 把隔墙 7.5 m 自动发现缩短到 2–3 m。
   - 手电光锥本身也会暴露玩家位置。
5. **给玩家逃生手段**：可以关上的门，桌子下等藏身点；怪物失去视线后减速并开始搜索。
6. **空间音频**：每只怪物挂一个 HRTF PannerNode，配上它自己的脚步声或低语。尖啸音量按距离衰减。
7. **死亡反馈**：怪物被击杀后化成 VHS 雪花噪点或碎片，加一声闷响，不再瞬间消失。

### 第 3 阶段：关卡与重玩性（约 1–2 周）

- **新的关卡生成器**：随机房间矩形 + 薄墙段 + 偶尔出现的柱子，底层仍然保留网格，用来寻路和做碰撞。
- **随机化关键位置**：
  - 磁带按 BFS 距离分档摆放（近、中、远各一，第四盘随机）；
  - 出口从远端边界格子里随机挑选；
  - 出生朝向也随机。
- **给目标加叙事**：每盘磁带拾取后播放一段 5–10 秒的 VHS 画面或录音，碎片化地讲故事，同时给玩家去找下一盘的理由。
- **复玩钩子**：结算页显示种子，加每日种子，用 localStorage 存最佳通关时间。
- **导航方式**：不加小地图，保持恐怖感。让磁带发出带空间定位的 VHS 噪音，玩家靠声音找路。

### 第 4 阶段：性能与工程

- **画质预设**（低 / 中 / 高）：低档关闭阴影、pixelRatio 设为 1、点光源上限 4 盏。按帧率自动降档。
- **怪物网格合并**：同一材质的部件用 `BufferGeometryUtils.mergeGeometries` 合成一个网格，只让主体投射阴影。改完后用 draw call 计数验证效果。
- **拆分引擎类**：拆成 `PlayerController`、`CombatSystem`、`EntityDirector`、`LevelBuilder`、`LightingSystem`。
- **测试**：用 vitest 测关卡生成（磁带和出口都可达、磁带之间有最小间距），再加上第 1 阶段的判定盒覆盖测试。
- **设置菜单**：灵敏度、主音量、FOV、Y 轴反转，结果存到 localStorage。

## 投入产出比最高的 5 件事

1. **修命中盲区**：改 3 行，手感马上改善。
2. **失焦自动暂停，重新锁定鼠标时不开枪**：约 20 行。现在玩家点一下画面就会把全图怪物引过来，这是最容易劝退的体验。
3. **README、在线试玩链接、清理仓库**：作品集价值最大的一步，基本不用改代码。
4. **收紧弹药 + 威胁导演**：用很少的代码就能让游戏从打靶变成生存。
5. **给 Smiler 加「怕光」机制，加空间音频**：手电变成两难选择，「听到身后有东西」也开始起作用。这是这个题材最该有的两样东西。
