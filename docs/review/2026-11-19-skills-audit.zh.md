## 结论

**有用，而且挺具体。** 四组技能共找出 32 条可改进点，其中有几条是我之前几轮都没注意到的真问题：

- 每日挑战在不同浏览器里地图不同；
- 开枪后视角永久上抬，不会回落；
- 按住空格会把半自动手枪变成连发；
- 每捡一盘磁带都会触发全部受光材质重编译着色器。

技能文档的价值在于给出了行业里的具体做法和数值，例如：

- 后坐力应作为偏移量，在 0.3–0.5 秒内恢复；
- 爆头倍率通常在 2–4 倍；
- 怪物发现玩家时应有 0.2–0.5 秒的反应延迟；
- 闪烁频率不应超过每秒 3 次。

这让改进方向从「感觉不对」变成了「可以照着改」。

## 第一批：明确的 bug 和低成本修复（每项改动小，建议先做）

| # | 问题 | 依据 | 位置 | 改法 |
|---|---|---|---|---|
| A1 ✅ | **每日挑战在不同浏览器里地图不同**。洗牌用的是 `sort(() => rng() - 0.5)`，排序结果由浏览器引擎决定，Chrome 和 Firefox/Safari 会得到不同的补给、门、怪物位置 | procedural-gen：同一种子必须得到同一地图 | [maze.ts:342](src/game/maze.ts:342)、[maze.ts:381](src/game/maze.ts:381) | 改用基于种子的 Fisher-Yates 洗牌；测试里固定几个种子的输出哈希。会改变现有种子对应的地图，所以纪录要换存储键 |
| A2 ✅ | **后坐力永久抬高视角**。每枪 +1.03°，从不回落，一个弹匣打完视角上抬 12°，玩家得手动往下拉 | fps-shooter：「后坐力应是会衰减到 0 的偏移量」 | [BackroomsEngine.ts:1632](src/game/BackroomsEngine.ts:1632) | 后坐力单独作为偏移量，约 0.4 秒恢复，叠加在视角之上 |
| A3 ✅ | **按住空格会连发**。空格没有过滤长按产生的重复按键事件，半自动手枪每秒约 4.8 发，还会每枪把 26 m 内的怪物都引过来 | input-systems：区分「按下」和「按住」 | [BackroomsEngine.ts:1518](src/game/BackroomsEngine.ts:1518) | 加 `!e.repeat`；冷却期内最后 0.1 秒的点击先缓冲，冷却结束后再打出 |
| A4 ✅ | **着色器重编译**。每捡一盘磁带，卡带里的点光源被隐藏，光源数量变化，所有受光材质重新编译。实测着色器程序数 38 → 51 → 62。本机上额外耗时 5–9 ms，弱设备会更明显 | performance-optimization：首次出现时的编译卡顿 | [BackroomsEngine.ts:894](src/game/BackroomsEngine.ts:894)、[BackroomsEngine.ts:2031](src/game/BackroomsEngine.ts:2031) | 拾取时把光源强度设为 0，不隐藏光源；画质设定改变后用 `compileAsync` 预热 |
| A5 ✅ | **电池被浪费**。只要电量没到 100% 就会吃掉电池，99% 时捡到等于白白浪费 44%，提示却说 +45%。低电量警告每个玩家一生只出现一次 | survival-crafting：资源降到 25–30% 时要有警告 | [BackroomsEngine.ts:2071](src/game/BackroomsEngine.ts:2071) | 电量低于约 73% 才自动使用（或允许携带备用电池）；提示显示实际增加量；每局在 25% 和 10% 各警告一次，电量条在低电量时变色 |
| A6 ✅ | **法线贴图闪烁**。程序生成的法线贴图默认最近邻过滤、没有 mipmap，地毯平铺约 32 次，移动时光照细节会闪烁、发块 | threejs / 性能：纹理要有 mipmap | [textures.ts:92](src/game/textures.ts:92) | 改为线性过滤 + mipmap + 各向异性过滤 |
| A7 | **爆头倍率 1.85 有断点**：打 Skin-Stealer 时，第 2 发爆头比 1 发爆头省不下任何一枪，而且爆头没有专门的反馈 | fps-shooter：爆头 2–4 倍；调整整张伤害表，而不是单个数字 | [entities.ts:788](src/game/entities.ts:788) | 倍率改成 2.0；加专门的爆头命中标记；把「几枪击杀」表做成测试 |
| A8 | **菜单焦点问题**：弹窗不能用 Esc 关闭，焦点会跑到弹窗后面的按钮上（首次打开时按 Shift+Tab 可能在说明面板后面直接开局），关闭后焦点也不会回到原来的按钮 | game-ui-ux：焦点必须困在弹窗内 | [SettingsPanel.tsx](src/components/SettingsPanel.tsx)、[HowToPlay.tsx](src/components/HowToPlay.tsx)、[App.tsx](src/App.tsx) | 弹窗打开时 HUD 设为 `inert`；Esc 关闭；关闭后把焦点还给原按钮 |
| A9 | **存档没有版本号和校验**：如果本地存储里的 `fov` 是 null，相机会在每次启动时坏掉；未知的画质值会穿透到渲染设置；每日纪录无限增长 | save-systems：每个存档都要有版本号、迁移和校验 | [storage.ts](src/game/storage.ts) | 存成 `{version, data}`；每个字段按设置面板的范围钳制；清理 30 天前的每日纪录 |

## 第二批：手感和公平性（中等工作量，玩家感知最强）

| # | 问题 | 依据 | 改法 |
|---|---|---|---|
| B1 | **怪物一看到就立刻追，贴脸当帧就能打**。拐角处遇到时没有任何反应时间；Smiler 在暗处 360° 都能看到 20 m 远 | game-ai：首次反应延迟 0.2–0.5 秒，或用一个近处涨得更快的警觉值 | 每只怪加 0–1 的警觉值：0.35 时进入「察看」并发出声音警示，到 1 才追击；进入追击后至少 0.45 秒才能出第一击 |
| B2 | **挨打时看不出攻击来自哪个方向**，伤害也没有前摇 | fps-shooter：重击要有前摇的声音或闪光 | HUD 按方向在屏幕边缘显示红色受击指示；在攻击者的位置播放抓挠声；可选 0.3 秒前摇，玩家拉开距离可以躲开 |
| B3 | **震屏太弱**：每帧随机抖动像噪点，连续受击不会叠加，开枪的震动几乎看不见；也没有「减少闪烁 / 减少晃动」的选项。按住射击时枪口光每秒约闪 4.8 次，可能超过每秒 3 次的光敏安全线；靠近怪物时手电以约 9.5 Hz 频闪 | game-feel：用逐渐衰减的震屏强度 + 正弦叠加，提供无障碍开关；game-ui-ux：提供减少闪烁选项 | 震屏改为强度累积的旋转抖动；新增震屏强度、减少晃动、减少闪烁三个设置 |
| B4 | **连续中弹让怪物几乎原地不动**：每枪硬直 0.18 秒、射击间隔 0.21 秒，冲过来的 Howler 只能前进 0.27 m，枪变成了「定身按钮」，偏街机感 | game-feel：命中停顿每次只触发一次 | 硬直加约 0.7 秒冷却，只有一串射击里的第一枪会让怪物硬直；被击中时加 0.05 秒的命中停顿和缓动的身体后仰 |
| B5 | **死亡几乎没有预警，结算页也没有教学价值** | survival-crafting：先预警再扣血，留出补救时间 | 低血量时加呼吸声和心跳层，屏幕边缘脉动变暗；死亡音效；结算页显示「被 Skin-Stealer 杀死」，并给出对应的应对方法 |
| B6 | **瞄准时的灵敏度和视野角换算不对**：开镜灵敏度固定为腰射的 0.636，按视野角换算默认应为 0.732，开镜时偏慢约 13%；视野角滑块实际是垂直视角，默认的 72° 相当于横向 104° | fps-shooter：开镜灵敏度乘以 tan(开镜 FOV/2) / tan(腰射 FOV/2) | 按实时视野角换算灵敏度；滑块标注为垂直 FOV，并显示对应的横向角度 |

## 第三批：性能（先测量，再优化）

| # | 问题 | 改法 |
|---|---|---|
| C1 | **没有区分瓶颈在 CPU 还是 GPU**，这决定了后面哪项优化值得做 | 调试接口加 `perf()`：draw call 数、三角形数、着色器程序数、CPU 和 GPU 每帧耗时，以及 p95 帧时间 |
| C2 | **画了大量被雾完全遮住的东西**：雾在约 28 m 外就几乎不透，相机远平面却在 55 m；每盏灯的光晕都是单独一个网格，可能有约 100 次绘制 | 远平面按雾的浓度设为约 28–32 m；光晕合并成一个实例化网格 |
| C3 | **怪物身上每个小部件都投影**，包括牙齿、爪子、眼睛，甚至脚下那块假阴影贴片，每只怪多约 74 次绘制 | 只让大的身体部件投影；静态部件按材质合并几何体 |
| C4 | **枪模由 32 个独立网格组成**，永远在屏幕上，约占总 draw call 的 20% | 按材质合并成约 8 个网格 |
| C5 | **每个像素都在逐盏计算点光源**：中档画质仍有 12 盏，其中磁带光源、出口光源和枪口光源大多数时间是关着的 | 把它们并入「离玩家最近的 N 盏灯」的灯池，删掉专用光源 |
| C6 | **主线程浪费**：每帧新建约 100 个对象并排序；每 60 ms 就让 React 重新渲染整个 HUD；暂停时仍然满帧渲染 | 预分配数组；只有数值变化时才推送 HUD；暂停和结算时只渲染一帧 |

## 第四批：更深的设计改进

| # | 问题 | 改法 |
|---|---|---|
| D1 | **压力只升不降，没有喘息** | 导演系统加一个强度值：强度过高时进入 15–20 秒的缓和期，太久没事发生就主动制造遭遇。拿磁带时新怪物不要和日志同时出现 |
| D2 | **多只怪物会互相穿透，叠成一团追过来** | 怪物之间互相推开；多只同时追击时分走不同的环路，形成包抄 |
| D3 | **关门几乎等于必定脱身**：只要存在其他路线，再远的绕路怪物也会走 | 寻路改成加权的 Dijkstra，把关着的门算作「撞开所需时间」的代价；缓存整条路径，并对路径做平滑，不再走直角楼梯 |
| D4 | **出口箭头直接指向墙里，迷宫里也没有地标** | 箭头改为指向通往出口路线上的下一段；每个象限的大厅给一个独特的标志物；在路口放上大多数时候指对方向的涂鸦 |
| D5 | **最后一盘磁带可能离出口只有几步**，「快跑」的高潮只有 2 秒 | 磁带到出口至少 8 步路程；测试里输出路线长度的分布 |
| D6 | **音频混音只有一条总线**：音量滑块是线性的，压缩器在枪声后会把环境声「吸」下去，暂停时磁带音源还在响；远处怪物的声音不会被剔除，隔墙时脚步声也没有变化 | 分成环境、音效、世界、界面四条总线；音量按平方曲线映射；母线只做限幅；暂停时压低音量；远距离剔除；隔墙时额外衰减音量；给重复的音效加随机变化 |
| D7 | **HUD 文字只有 11–12 px**，部分文字对比度不足 | 增加 HUD 缩放设置；字号下限 14/16 px；对比度至少 4.5:1 |
| D8 | **不能改键**；瞄准、冲刺、蹲伏都不能切换按住/点按 | 按动作绑定按键，提供改键界面，检测按键冲突 |

## 技能认为已经做得好的

- 颜色管理正确（sRGB 输出、ACES 色调映射、数据贴图保持线性）；静态迷宫几何体用了实例化；只有一盏光源投影；循环里限制了帧间隔。
- AI 只通过 `EntityWorld` 接口查询关卡，感知、决策和寻路分层清楚；定时重新寻路，移动时不会冲过路点。
- 每次开枪的反馈是多层组合（套筒、后坐、枪口焰、光、弹壳、声音），全部会复位；平滑全部与帧率无关。
- 威胁随进度上升，而且有明示（威胁条、提示文案）；生存数值按游戏时钟消耗，暂停时冻结。
- 状态显示大多不只靠颜色（WINDED、HIDDEN 等文字标签）；存储读写都有容错。

## 建议的顺序

1. **第一批（A1–A9）**：都是实打实的 bug 或很低成本的修复，大约一轮就能完成。A1 会改变每日挑战的地图，最好趁现在玩家还少的时候做。
2. **C1 测量 + B1/B2/B3**：先弄清楚性能瓶颈在哪，再做对恐怖体验影响最大的三项（反应时间、受击方向、震屏和无障碍）。
3. 其余按需要推进。

所有改动都应走 PR，合并前跑 CI 检查。
